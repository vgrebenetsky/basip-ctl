# basip-ctl — етап 2

Неофіційна консольна утиліта для групового керування пристроями BAS-IP.
Не пов'язана з виробником; BAS-IP — торговельна марка її власника.

Групове керування пристроями BAS-IP: усі команди ТЗ v4 реалізовано.
Якщо ім'я файлу не вказано, використовується `devices.csv` з поточного каталогу
(`--no-file` — працювати без файлу, лише з `--ip` і `--password`).

## Збірка (Linux, Go 1.21+)

    go build -o basip-ctl .

або встановлення напряму з GitHub:

    go install github.com/vgrebenetsky/basip-ctl@latest

Зовнішніх залежностей немає. Для збірки під інший Linux-сервер:

    GOOS=linux GOARCH=amd64 go build -o basip-ctl .

## Приклади

    ./basip-ctl ping devices.csv
    ./basip-ctl ping devices.csv --ip 192.168.10.11-16
    ./basip-ctl info devices.csv --ip 192.168.10.11
    ./basip-ctl info devices.csv --json > info.json
    ./basip-ctl info devices.csv --update            # записати фактичні тип/модель/версію API у файл
    ./basip-ctl auth devices.csv --report auth.csv
    ./basip-ctl auth --ip 192.168.10.50 --password <пароль або хеш>
    ./basip-ctl auth devices.csv --ip 192.168.10.50 --password <хеш>   # додасть пристрій у файл

## Команди

| Команда | Кому | Примітка |
|---|---|---|
| `ping`, `info`, `auth` | вибраним | `info --update` оновлює тип/модель/версію API у файлі |
| `door-status` | вибраним | стан датчика дверей |
| `backup` | вибраним | один архів `backup_<дата_час>.zip`, тека на пристрій: `settings.zip`, `users.zip`, `manifest.json`; `--settings` / `--users` |
| `emergency-on` / `emergency-off` | лише `emergency=1` | замки з колонки `lock`; `--duration` (типово 43200 с) |
| `open` | `--ip` обов'язковий | замки з колонки `lock`; `--unlock-time` |
| `restore` | `--ip` обов'язковий | `--from backup_….zip`: кожному пристрою — його копія; перед відновленням — свіжа копія `…_before-restore.zip` (`--no-backup` вимикає) |
| `reboot` | `--ip` обов'язковий | `--wait` — дочекатися повернення в мережу (до 5 хв) |
| `clear-logs` | `--ip` обов'язковий | панелі: очищення syslog (`/syslog/clear`) і налагоджувального журналу; `--save` — зберегти налагоджувальний журнал перед очищенням; на CR-02BD недоступно |
| `passwd-manager` | `--ip` обов'язковий | вимкнений manager пропускається, `--force` — змінити все одно |
| `passwd-admin` | `--ip` обов'язковий | старий пароль вводиться один раз; змінюються лише пристрої з відповідним хешем; після зміни — перевірка входу й запис хешу у файл |

Усі змінюючі команди питають підтвердження (`--yes` — без питань) і підтримують `--dry-run`.
Пристрої з `OK` у полі пароля пропускаються в усіх командах з входом.

## Файл пристроїв

Розділювач `;`, перший рядок — заголовок:

    ip;device_type;device_name;api_version;lock;status;emergency

* колонка пароля може називатися `status` або `password`;
* 32 шістнадцяткові символи — MD5-хеш, інакше — пароль (MD5 рахується автоматично);
* `lock`: `1`, `1,2`, `0` (усі замки); порожньо = 1;
* `emergency`: `1` — дозволено;
* `OK` у полі пароля — пристрій пропускається в усіх командах, що потребують входу
  (статус «пропущено»); `ping` та `info` для нього працюють.

Перед будь-якою зміною файлу створюється копія `.bak`; попередні копії зсуваються
у `.bak1`, `.bak2` ...

## Перевірка доступності

ICMP через системну утиліту `ping`. Якщо прав на ICMP немає — перевірка TCP 80/443
(відмова у з'єднанні теж означає, що пристрій у мережі). Спосіб показується на початку виводу.

## Профілі API (endpoints.json)

Шляхи викликів вбудовані у програму окремо для сімейств:

| Профіль | Пристрої | Вхід |
|---|---|---|
| android-v2 | panel, API 2.x (AA-12FB) | POST /api/v1/login, JSON |
| controller-v1 | accesscontroller (CR-02BD) | GET /api/v1/login?username&password |
| legacy-v0 | panel, API 0.x/1.x | GET /api/v0/login?username&password |

Якщо пристрій відповідає 404/405 або «відсутні параметри», програма один раз пробує
інший формат входу. Після відмови через невірний пароль повторів немає (захист від блокування).

Щоб змінити шлях без перезбирання, покладіть поруч з програмою `endpoints.json`
(див. `endpoints.example.json`): у ньому достатньо вказати лише операції, що змінюються.

## Журнал і звіт

* `basip-ctl.log` — у поточному каталозі; паролі, хеші й токени не записуються;
* `--report файл.csv` — результати по кожному пристрою (відкривається в Excel).

## Коди завершення

`0` — усе успішно, `1` — є помилки на частині пристроїв, `2` — помилка параметрів або файлу.

## Безпека

Не публікуйте `devices.csv`, `*.bak`, `basip-ctl.log` і архіви резервних копій —
вони містять хеші паролів і дані об'єктів. Вони вже виключені у `.gitignore`.

## Карта запитів API

`basip-ctl api-map` друкує для кожного типу пристроїв, які запити надсилає програма:
основний шлях і запасні варіанти (пробуються лише коли пристрій відповідає 404/405).
Змінити шляхи без перезбирання можна у файлі `endpoints.json` (див. `endpoints.example.json`).
